# 上线准备对话备忘

本文记录 2026-06-03 关于 Prompt Hub 是否适合上线的评估结论，供后续继续优化上线产品时快速接上下文。

## 总体判断

项目的核心产品链路已经基本成型，主要风险不在大块功能缺失，而在生产环境配置、支付闭环、正式域名与扩展联动、以及上线前端到端验收。

当前更适合先做小范围灰度、staging 或内测；如果要正式公开商业上线，需要先补齐 P0 项并跑完整 smoke。

## 已基本通顺的流程

- 扩展 BYOK 路径较成熟：用户自备 API Key 即可完成安装设置、添加参考图/视频、反推、AI 改写、历史版本、提示词库等核心操作。
- 平台内置服务路径代码层基本闭环：官网登录、API Key/点数、扩展同步、代调用扣点、余额刷新、后台观测都有对应实现。
- 官网与运营后台已有基础能力：账户、充值订单、点数流水、上游模型、用户调账、请求日志等模块已经形成运营骨架。

## 上线前 P0 缺口

1. **上游服务必须配置并验证**
   - 生产如果没有配置 `UPSTREAM_API_KEY` 或后台上游 Key，平台内置服务会 503。
   - 需要在 Admin 录入上游 Key、同步模型，并完成一次真实反推扣点。

2. **支付策略必须明确**
   - 当前默认配置更接近 staging。
   - 如果微信/支付宝未开通，订单会进入人工待处理，不能自动加点。
   - 正式上线前需要二选一：接通真实支付，或明确人工充值 SOP（订单确认、调账、备注、用户通知）。

3. **正式域名与扩展 manifest 必须对齐**
   - 扩展与官网的 Key 回传依赖 `externally_connectable` 域名。
   - Zeabur 临时域名阶段无法完整验证扩展和官网同步。
   - 切到真实域名前，仓库内占位为 `github.com/xiaotao-02/prompt-hub`；上线前须全局替换并跑 `npm run check:launch-domain`。
   - 替换后需要重新 `npm run release:store` 并发布扩展。

4. **生产登录方式必须可用**
   - 至少确认 Google OAuth、SMTP 邮箱登录或其他真实登录路径之一可用。
   - 不应依赖 dev 登录或只打印验证码的短信逻辑面向真实用户。

5. **数据备份必须落地**
   - SQLite 中包含订单、点数、账本等资产数据。
   - Zeabur Volume、备份策略或等价方案必须在正式上线前确认。

6. **上线 smoke 不能只测 `/health`**
   - 需要覆盖登录、充值或试用、扩展同步、模型列表、反推扣点、余额刷新、历史写入、后台日志。

## 主要体验与运营摩擦

- 扩展内直接登录使用短期 JWT，官网 `from_ext` 同步使用 `pe_live_*` API Key，两条路径体验和权限模型不完全一致。
- 人工充值缺少“一键确认订单并加点”的完整运营动作，可能导致订单状态与账本调账双轨。
- 新用户试用防滥用后端已有，但后台对试用发放、拒绝原因、IP/设备命中情况的可观测性还不够。
- `POINTS_PER_USD` 等商业配置口径需要统一，避免文档、默认值与实际生产配置不一致。

## 建议上线顺序

1. 先以 BYOK 路径作为最稳的基础版本，保证扩展核心体验稳定。
2. 配置正式 API 上游，并在 Admin 完成模型同步与连通测试。
3. 明确支付方案：真实支付优先；若暂时人工充值，需要写清运营 SOP。
4. 切正式域名，更新官网/API/扩展配置，并重新发布扩展。
5. 跑完整端到端 smoke：官网登录 → 扩展同步 → 反推扣点 → 充值刷新 → 后台审计。
6. 再补 P1 优化：统一平台登录推荐路径、后台人工订单确认、试用风控可视化、备份告警。

## 上线 smoke 清单

- 官网首页、`/account`、`/pricing` 可访问。
- `GET /health` 返回 200。
- 生产登录成功，且无 dev 登录入口。
- 新用户注册后试用点按预期发放或拒绝。
- 充值路径可完成：真实支付到账，或人工充值 SOP 可闭环。
- 扩展通过官网 `?from_ext=` 同步 `pe_live_*` Key。
- Options 显示内置服务已连接，余额正确。
- 模型列表可拉取并选择。
- 网页右键或框选添加参考图/视频。
- 面板反推成功，余额减少。
- AI 改写成功，历史版本增加。
- Popup 可召回历史到面板。
- Options 提示词库可见历史记录。
- Admin 可看到用户、订单、流水、请求日志和上游状态。

## 后续优化优先级

- P0：上游配置、支付策略、正式域名、扩展发版、完整 smoke。
- P1：统一平台登录路径，弱化短期 JWT 登录或明确标注有效期。
- P1：Admin 增加人工订单确认并自动加点。
- P1：Admin 展示试用风控与发放记录。
- P2：SQLite 自动备份、上游额度告警、更多上游协议 adapter。
