# 官网官方 API 与账户页优化计划

## Lago 参考结论

- 已阅读 Lago 的 [API standards](https://getlago.com/docs/api-reference/api-standards)：核心不是装饰视觉，而是清楚交代 `Authorization: Bearer <your_api_key>`、HTTP 状态码、JSON request/response、查询参数与分页/过滤口径。
- 已查看 Lago 文档索引：它围绕 `customer usage`、`events`、`wallets`、`API logs`、`errors`、`pagination` 组织“计量 + 余额 + 账务 + API 可观测性”。Prompt Hub 当前最贴近的是平台余额、充值订单、API Key、模型用量统计和扩展同步。
- 已补充查看 Lago 的 `errors`、`customer usage`、`wallet` 相关文档：UI 组件上更像“文档型 API 块 + 账务控制台块 + 用量观测块”，而不是普通营销页卡片。
- 因此本次不做 Lago 代码/资产复刻，而是借鉴它的 API-first 信息架构和组件语义：让【官方 API】页像“接入与计费文档入口”，让【账户】页像“轻量 billing console”。

## UI 组件参考

- `API standards` 组件：认证 Header 代码块、JSON request/response 示例、HTTP 状态码分组、查询参数说明块。
- `Developer console` 组件：API Key 区、Bearer Token 示例、Endpoint/Method 小标签、复制/生成操作状态。
- `Wallet / Top-up` 组件：余额卡、充值档位、自定义金额、支付通道、交易状态 badge、充值记录。
- `Usage / Metering` 组件：实时用量摘要、周期切换、模型消耗/请求排行、趋势图、tokens 指标与空状态。
- `Errors / Logs` 组件：错误码示例、最近调用记录、状态码说明，帮助用户理解调用失败和余额不足等状态。

## 视觉与内容方向

- 视觉主张：深色、克制、偏开发者控制台与 billing console，用清晰的状态、计量、代码片段和账务轨迹替代泛营销卡片。
- 内容结构：首屏先说明“平台代调用 = Bearer Key + JSON API + 钱包扣点 + 扩展自动同步”；核心区突出余额、充值、API Key、订单记录；账户页登录后突出用量趋势、模型分布、最近调用和低余额提醒。
- 组件层级：减少孤立玻璃卡片堆叠，改成“左侧标准/说明、右侧操作面板”或“顶部指标、下方观测”的控制台布局。
- 交互方向：沿用现有淡入动画，增加选中/hover/状态徽标；不改变 `account.ts`、`apiAccountPanel.ts`、`recharge.ts` 依赖的 DOM id。

## 具体改动

- 重做 `[website/src/pages/pricing.astro](website/src/pages/pricing.astro)`：
  - 首屏加入 API standards 风格的“接入规范”模块，例如认证 Header、JSON 请求、状态码、查询/分页口径。
  - 新增开发者接入组件：展示 `Authorization: Bearer <api_key>`、`Content-Type: application/json`、当前 API Endpoint，以及简短调用示例。
  - 充值工作区改为 wallet/top-up 语义：余额、点数包、自定义金额、支付方式、订单状态在同一个操作流中呈现。
  - FAQ 与计费说明改为更接近 Lago 文档组件的状态码/错误/扣点口径说明，降低“宣传页”感觉。
  - 保留 `#api-account-app`、`#api-login-prompt`、`#api-account-panel`、`#recharge-section`、`#order-history` 等脚本锚点。
- 重做 `[website/src/pages/account.astro](website/src/pages/account.astro)`：
  - 未登录状态改为“从扩展连接账户”的 onboarding，强调邮箱/Google 登录后自动同步平台 Key。
  - 登录后改成 billing console：顶部身份与会话状态，三项核心指标，低余额提醒，用量分析，最近调用记录。
  - 将现有模型数据分析区包装成 Usage / Metering 组件：周期切换、图表标题、总量、排行榜/趋势更像用量控制台。
  - 文案采用 Lago 文档式的具体口径：余额、请求数、tokens、模型消耗、最近记录，而不是笼统“管理账户”。
- 收敛 `[website/src/styles/global.css](website/src/styles/global.css)`：
  - 新增 API standards、developer console、wallet/top-up、usage dashboard、error/log block 相关布局类。
  - 整理重复的 `.account-shell` 历史定义，保留向后兼容类名。
  - 保持全站深色品牌调性和 Tailwind v4 写法。
- 不改业务脚本：
  - 不修改认证、充值、订单轮询、API Key 生成、扩展同步逻辑。
  - 如果视觉结构需要新增包裹层，优先添加 class，不移动或重命名脚本查询的 id。
