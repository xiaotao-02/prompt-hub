# 本地平台登录预填计划

## 目标

让 `http://localhost:5173/__dev__/ui-preview#options` 的“平台账户”表单在本地预览环境中默认填入 `dev@local.test` 和 `123456`，减少测试输入成本，但仍要求用户点击“发送验证码”和“登录”，确保 `PLATFORM_LOGIN_EMAIL_SEND`、`PLATFORM_LOGIN_EMAIL_VERIFY`、`applyPlatformLogin()`、`fetchProviderQuota()` 这条链路继续被测试到。

## 修改范围

- 修改 `[src/components/PlatformLoginForm.tsx](src/components/PlatformLoginForm.tsx)`：
  - 引入平台 API 配置，判断是否为本地预览环境。
  - 将 `email` 初始值设置为 `dev@local.test`，`code` 初始值设置为 `123456`，仅在本地预览生效。
  - 保留现有按钮逻辑，不自动发送验证码、不自动登录。
  - 可增加一行很轻的本地测试提示文案，避免误以为生产也会预填。

- 如有必要，补充 `[.cursor/skills/local-platform-dev-login/SKILL.md](.cursor/skills/local-platform-dev-login/SKILL.md)` 中的登录步骤说明：本地预览会预填邮箱和验证码，仍需点击两步按钮。

## 环境判断

采用保守判断，避免影响真实扩展或线上网站：

```ts
const isLocalPlatformPreview =
  globalThis.location?.hostname === 'localhost' &&
  PLATFORM_API_URL.startsWith('http://localhost:8787');
```

这样只有通过 `npm run dev:previews` 启动、且 Vite 注入本地 API 地址时才会预填。

## 验证

- 运行 `npm run lint:types`。
- 启动 `npm run dev:previews` 后打开 `http://localhost:5173/__dev__/ui-preview#options`。
- 进入“平台账户”，确认邮箱已是 `dev@local.test`；点击“发送验证码”后验证码输入框出现且已是 `123456`；点击“登录”后余额 badge 从本地 API 刷新。
