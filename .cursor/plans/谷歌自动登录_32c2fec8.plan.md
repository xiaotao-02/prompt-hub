# 官网 Google 自动登录计划

## 当前判断

- 官网账户页在 [`website/src/pages/account.astro`](website/src/pages/account.astro) 已加载 `https://accounts.google.com/gsi/client`，并通过 `window.google.accounts.id.renderButton(...)` 渲染 Google 登录按钮。
- 后端 [`services/api/src/routes/auth.ts`](services/api/src/routes/auth.ts) 已有 `POST /v1/auth/google`，会校验 Google credential、创建/解析用户并返回平台 JWT。
- 因此优先不改后端协议，只在官网账户页新增自动弹出账号选择逻辑；现有 Google 按钮、邮箱魔法链接、手机号登录继续作为兜底。

## 实施步骤

1. 修改 [`website/src/pages/account.astro`](website/src/pages/account.astro) 的 `initGoogle()`：
   - 在 `window.google.accounts.id.initialize(...)` 中补充适合自动登录提示的配置，例如 `auto_select: false`、`use_fedcm_for_prompt: true`、`cancel_on_tap_outside: true`。
   - 在按钮渲染后，对未登录用户调用 `window.google.accounts.id.prompt(...)`，触发 Google 账号选择/一键登录提示。
   - 用一个页面级状态避免 `tryInit()` 轮询期间重复初始化、重复弹出。

2. 保持登录成功后的现有行为：
   - Google callback 继续把 `response.credential` 提交到 `/v1/auth/google`。
   - 成功后调用 `setToken(data.token)`，页面切到已登录状态并展示 API Token。
   - 失败时只显示错误，不影响邮箱和手机号登录。

3. 增加体验与兼容兜底：
   - 仅在 `token()` 为空时自动 prompt，已登录用户不弹。
   - 如果 Google One Tap/FedCM 因浏览器策略、未配置授权来源、用户关闭过提示等原因不展示，保留页面上的 Google 登录按钮。
   - 可在 prompt callback 中记录 `isNotDisplayed()` / `isSkippedMoment()`，给 `auth-msg` 显示简短提示，例如“可点击下方 Google 按钮登录”。

4. 验证：
   - 在 `website` 目录运行 `npm run build`，确认 Astro 静态站构建通过。
   - 手动打开 `/account`：未登录时应自动出现 Google 账号选择提示；点击账号后应登录并展示余额与 Token。
   - 验证已登录刷新不再弹出；退出登录后再次可触发；Google prompt 不出现时按钮仍可登录。

## 注意事项

- 生产环境必须同时配置官网 `PUBLIC_GOOGLE_CLIENT_ID` 与 API `GOOGLE_CLIENT_ID`，且 Google Cloud OAuth Web Client 的 Authorized JavaScript origins 包含官网域名。
- Google 的自动账号提示受浏览器、第三方 Cookie/FedCM、用户历史关闭行为影响，代码只能请求弹出，不能强制每次都显示。
